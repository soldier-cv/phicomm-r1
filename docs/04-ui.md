# 我们自己的程序 —— 界面与交互设计

> 目标：**一眼看到状态、一句话就能用、改坏了能退回来。**
>
> **本文只讲设计与取舍**；页面长什么样、有哪些控件，以 `web/desktop`、`web/mobile` 的实现为准。
> 运行时链路见 `docs/22-call-chains.md`。

---

## 一、先看现役那个页面差在哪（免得重犯）

我把它的 22 个接口和页面结构都读过，问题集中在六点：

| 问题 | 具体表现 |
|---|---|
| **没有状态** | 打开页面不知道设备在不在线、内存在多少、上次对话是什么。全靠猜。 |
| **没有反馈** | 保存只弹一个 `alert('保存成功')`，不显示改了什么、什么时候生效。 |
| **危险操作没隔离** | `/qw_pubkey?gen=1` 会**覆盖私钥文件**，按钮就摆在普通表单里。 |
| **没有对话入口** | 六个标签全是"配置"，没有一个地方能"试一下"。 |
| **信息平铺** | 6 个标签同样重要，找一样东西要点开三个。 |
| **主页是测试页** | 设备屏幕上显示的是作者的 `Pandora` 调试面板，不是给人用的。 |

**我们的设计原则（逐条对着治）**

1. **状态永远可见** —— 顶部一条常驻状态栏
2. **每个动作都有回执** —— 内联显示"已生效 / 失败原因"，不用弹窗
3. **危险操作全部收进「高级」并二次确认**
4. **首页就能对话** —— 最重要的功能放第一屏
5. **按使用频率分层** —— 常用在第一屏，配置收进二级
6. **失败要能看见原因** —— 不吞异常，把设备返回的原始错误显示出来

## 二、信息架构

```
┌─ 状态栏（全局常驻）
│    ● 在线   L1 待接入   内存 8.3M   正在播放：无
│
├─ 首页          ← 打开就是这里
│   ├ 状态卡（设备/内存/网络/版本）
│   ├ 对话输入框（一句话 → 回答 → 播报）
│   └ 快捷开关（灯 / 音量 / 静音 / 休眠）
│
├─ 对话
│   └ 历史列表（可重发、可重播）
│
├─ 语音
│   ├ TTS 源（本地服务 / OpenAI 兼容 / 云厂商）  ← 你要的"设置的地方"
│   ├ 音色、语速、音量
│   └ 唤醒词（依赖 L1，未接入时置灰）
│
├─ 音乐
│   ├ 源（本地文件 /sdcard/Music）
│   └ 黑胶转盘 + 唱针动效 + 声学频谱 + 实时 LRC 歌词滚屏
│
└─ 设置（系统运维中枢）
    ├ 卡片 01: AI 大模型路由引擎 (LLM 预设/端点/Key/人设)
    ├ 卡片 02: TTS 语音合成引擎 (端点/音色/语速/试听)
    ├ 卡片 03: 北京时区定时闹钟与睡眠定时 (RTC_WAKEUP 准点调度)
    ├ 卡片 04: Home Assistant 智能家居与城市天气 (免Key开放源 + 测试天气按钮)
    ├ 卡片 05: 运维中枢 · 应用管理与静默 OTA 升级 (流式拖拽上传/应用强停与卸载/一键深度清理/特权重启)
    └ 卡片 06: 实时系统日志终端 (Logcat) 与设备连接调试
```

**为什么这样分**：首页和对话是"每天用十次"的，语音和音乐是"一周调一次"的，
集成是"装好就不动"的，系统是"出问题才来"的。

## 三、首页（最重要的一屏）

```
┌──────────────────────────────────────┐
│ ● 在线 · 已运行 2 小时                │   ← 状态栏
│ L1 待接入    内存 8.3M    版本 0.1.0  │
├──────────────────────────────────────┤
│                                      │
│  说点什么                            │
│  ┌────────────────────────────────┐  │
│  │ 帮我讲个笑话                    │  │
│  └────────────────────────────────┘  │
│                        [ 发送并播报 ] │
│                                      │
│  ┌ 我 ─────────────────────────────┐ │
│  │ 帮我讲个笑话                     │ │
│  └─────────────────────────────────┘ │
│  ┌ 助手 ───────────────────────────┐ │
│  │ 有一只鸭子走进酒吧……             │ │
│  │ 🔊 播报中  · 1.2s               │ │
│  └─────────────────────────────────┘ │
│                                      │
├──────────────────────────────────────┤
│  快捷操作                            │
│  [ 聊天 ]  [ 氛围灯 ]  [ 静音 ]      │
│  [ 音量 ──●──── ]  [ 休眠 ]          │
└──────────────────────────────────────┘
```

**交互细节**

| 动作 | 反馈 |
|---|---|
| 点「发送并播报」 | 输入框立即变灰，气泡先显示"思考中…"，1~2 秒后替换为回答 |
| 回答生成完 | 自动播报；气泡上出现 `🔊 播报中`，结束变 `🔊 重播` |
| 出错 | 气泡变红，显示 **原始错误**（如 `HTTP 401`），下面给一条"去检查 Key"的链接 |
| 设备离线 | 顶部状态栏变红并显示"连不上"，发送按钮禁用 |

## 四、语音页（TTS 设置）

这是你点名要的「设置的地方」。TTS 三种形态，用一次单选切换：

```
┌──────────────────────────────────────┐
│ 语音输出                              │
│                                      │
│  （ ）设备自带      — 不可用（本机无引擎）│
│  （•）局域网 TTS 服务                 │
│  （ ）OpenAI 兼容接口                 │
│  （ ）云厂商                          │
│                                      │
│  地址                                 │
│  ┌────────────────────────────────┐  │
│  │ http://<TTS服务IP>:9880/tts │  │
│  └────────────────────────────────┘  │
│  协议  [ POST JSON ▾ ]               │
│  音色  [ 女声-A ▾ ]                   │
│  语速  ────●────── 1.0                │
│  格式  [ mp3 ▾ ]                      │
│                                      │
│  [ 试听一句 ]   ← 立刻播"你好，我是小讯" │
│                                      │
│  上次试听：成功，320 KB，1.8 秒        │
├──────────────────────────────────────┤
│ 唤醒词（需要 L1）                     │
│  [ 小讯小讯        ]   ⚠ 未接入，暂不可改 │
└──────────────────────────────────────┘
```

**为什么要有「试听」**：TTS 配错是最常见的问题（地址错、格式不认、需要鉴权）。
一个按钮就能定位到是哪一环坏了，比看日志快十倍。

**支持的三种协议**（内部统一成 `TtsProvider`）

| 协议 | 请求 | 响应 |
|---|---|---|
| 本地 TTS（自定义） | `POST {url}` `{text, voice, speed}` | `audio/*` 字节流 |
| OpenAI 兼容 | `POST {base}/audio/speech` `{model, input, voice}` | `audio/mpeg` |
| 云厂商 | 各自签名，封装在适配器里 | 拿到字节流 |

> 你要在本地装的那个 TTS，如果是 GPT-SoVITS / edge-tts / ChatTTS 之类，
> 大多能套第一个或第二个协议。**告诉我具体是什么服务，我把适配器写死。**

## 五、其余页面要点

### 对话页
- 列表倒序（最新在上），每条带时间戳、耗时
- 每条回答右侧有「重播」「复制」
- 顶部有「清空」（二次确认）
- 上限 **50 条**（内存只有 8MB，不能无限存）

### 音乐页
- 源卡片：Navidrome（地址/账号/密码）、网易云、QQ
- 当前播放：封面、标题、进度条、上一首/播放/下一首
- 搜索框 → 结果列表 → 点击播放

### 集成页
- 大模型：provider / base_url / key / model / temperature / max_tokens
- **Key 输入框默认打码，带「显示」眼睛图标**
- 保存后有「测试连通」按钮（发一句"ping"，看能否返回）
- HA：地址 / 长期令牌 / 对话代理 ID
- 天气：和风 Key（可选）

### 系统页
- **实时日志**（SSE 或轮询，默认只显示 `R1BRAIN`）
- 版本号、安装时间
- 升级：上传 apk → 校验签名 → 安装（这就是 D-08 的落地）
- 重启服务 / 重启设备（后者二次确认）
- 高级（折叠）：清空配置、导出配置、**危险操作**

## 六、技术形态

| 选项 | 说明 | 取舍 |
|---|---|---|
| **A. 页面内嵌在 L2**，由 L2 的 8686 提供 | 单机自足，局域网直接访问 | ✅ **选这个**（第一期） |
| B. 页面放 L3，L3 反向代理到 L2 | 省内存，能存历史 | 第二期再说 |

内嵌的代价：大约 **1~2 MB 内存**（静态资源 + HTTP 线程）。
加上现在只剩 8MB，这是第一期最大的风险点（对应 O-13）。

**降级预案**：如果加上去之后 L2 频繁被系统杀，就改成
「页面放 L3，L2 只提供 JSON API」—— 前端换个地方托管，代码不用重写。

## 七、页面与模块（当前实现）

> 以 `web/` 源码为准；每页都由 `node web/build-pages.js` 生成静态 HTML。
> 历史页面对照（旧 8080 那套）已归档：`archive/ui-design-prompt.md`、`archive/device-mod-era.md`。

| 页面 | 桌面/移动 | 核心模块 |
|---|---|---|
| 首页 | `desktop/home` · `mobile/home` | 文本指令坞、唱片台（进度/频谱/歌词行）、主音量、蓝牙、睡眠定时、灯环快捷、快捷指令、遥测脚注 |
| 对话 | `desktop/chat` · `mobile/chat` | 问答气泡、快捷指令、自动播报开关、重播/复制、耗时 |
| 音乐 | `desktop/music` · `mobile/music` | 音源切换（本地/HTTP 流/云音乐）、黑胶唱盘、LRC 歌词、曲库列表、云音乐搜索与登录 |
| 设置 | `desktop/settings` · `mobile/settings` | 大模型、TTS、闹钟、Home Assistant 与天气、运维中枢（应用管理 / OTA / 清理 / 重启）、日志、令牌 |

**能力落点**（说这些功能在哪）：

- 灯环：首页快捷区（4 种预置效果），经 L1 控制
- 点歌：音乐页搜索框 + 语音「放一首…」
- 闹钟：设置页卡片 + 语音（中文数字、一次性）
- 天气：设置页城市/Host + 语音「杭州天气」
- 智能家居：设置页 HA 地址与令牌 + 语音「打开客厅灯」
- 运维：设置页「运维中枢」（应用强停/卸载、APK 上传升级、深度清理、重启）

## 八、视觉方向

### 8.1 定调

**深色 + 暖金**。理由：这是一台**音响**，不是后台管理系统。
深色让它在客厅里不刺眼，暖金在黑色上最像"贵的东西"（参考 B&O、Naim 那类设备）。

> 现役那个页面是 `#f0f2f5` 浅灰 + `#1890ff` 蓝，是典型的"后台模板"配色，
> 放在音响上完全不搭。

### 8.2 设计令牌

| 用途 | 值 | 说明 |
|---|---|---|
| 背景 | `#0A0A0B` | 接近纯黑，带一点点暖 |
| 卡片 | `#141416` | 与背景只差 10 个亮度，靠 1px 边框分层 |
| 边框 | `rgba(255,255,255,.07)` | 细，不抢视线 |
| 主文字 | `#EDEAE4` | 暖白，不是纯白（纯白在深色上刺眼） |
| 次文字 | `#8A867E` | |
| 强调色 | `#D8A657` | 暖金，只用在**当前状态**和**主操作**上 |
| 成功 / 危险 | `#6FBF8B` / `#D9705F` | 低饱和，不用大红大绿 |
| 圆角 | 16px（卡片）/ 12px（输入）/ 5px（气泡尾） | |
| 字距 | 标题 `-0.02em`，小标签 `+0.08em` | 大字号收紧、小字号放开 |

### 8.3 三条视觉规则

1. **金色只给"活着的东西"** —— 正在播放、当前标签、主按钮。别的地方一律灰。
2. **层次靠亮度和边框，不靠阴影** —— 设备渲染能力有限，重阴影会掉帧。
3. **数字用等宽** —— 时间、进度、内存，用 `font-variant-numeric: tabular-nums`，跳动时不抖。

### 8.4 动效

只有两处，都很轻：

- 播放中的**六根音柱**（`transform: scaleY` 循环，不触发重排）
- 切换标签的**淡入上移 6px**（0.28s）

**不做**：页面转场、骨架屏、粒子效果 —— 这台机器扛不住。

### 8.5 体积目标

整个前端 **< 60 KB**（未压缩）。实际原型 **18.6 KB**（压缩后 5.7 KB 的 zip）。
不打包字体、不用图标库，图标全部内联 SVG。

### 8.6 当前实现

```
源码：web/src/（layout-desktop.js / layout-mobile.js / desktop-pages.js / mobile-pages.js / base-tailwind.css）
构建：node web/build-pages.js  →  web/desktop/ + web/mobile/ + web/assets/blackgold.css
自检：node web/verify-css.js && node web/verify-pages.js
打包：l2-app/build.ps1 会把 web/ 产物复制进 APK 的 assets（l2-app/assets 是构建产物，不进 git）
```

手机/桌面共 8 页：首页、对话、音乐、设置，固定黑金一套；手机底部 4 标签、桌面左侧机架导航。
不再保留 `prototype/` 下的历史原型文件。

**硬约束：不许引 Google CDN。** `fonts.css` 内嵌字体，图标用 Material Symbols 子集码位，
封面用 CSS 唱盘，全部资源本地化。

## 十、当前实现（黑金 v1，2026-10-30）

| 项 | 现状 |
|---|---|
| 页面 | `web/src` 生成桌面/移动各 4 页：首页、对话、音乐、设置 |
| 字体 | Space Grotesk + Manrope + JetBrains Mono 内嵌 base64，**零外链** |
| 布局 | 手机：顶部状态栏 + 单列卡片 + 底部 4 标签；桌面：左侧导航 + 顶部状态栏 + 主工作区 |
| 已接真接口 | `/status`、`/chat`、`/history`、`/config`、`/music/list`、`/music/lyrics`、`/player/*`、`/tts`、`/tts/stop`、`/volume`、`/bluetooth`、`/logs` |
| 鉴权 | `/api/**` 必须带 token（未带 401）；`/?token=` 打开后下发 Cookie，页面自动鉴权 |
| 滚动 | 聊天/日志/曲库只在数据变化时重建；用户上翻时不被轮询拉回底部 |
| 未接通 | 唤醒/ASR/灯环（需 L1）；天气/HomeAssistant 只有配置项 |
| 浏览器 | 现代 Chrome/Edge/Safari；不承诺 Android 5.1 老 WebView 排版 |

> 原型是设计语言，不是功能承诺：虚构能力和拿不到的数据全部删掉或标灰，这是本版对齐原型的原则。
