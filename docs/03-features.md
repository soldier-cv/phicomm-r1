# 功能规格（functional spec）

> 每个功能写清楚：**怎么触发、需要什么前提、点了之后发生什么、失败怎么办、怎么算做完。**
> 这不是功能清单（那是 `archive/features-v1.md`），这是拿来实现的。

---

## 零、先定三条规矩

1. **一个功能只归属一层**。要设备身份的归 L1，纯软件的归 L2。不许两边都做。
2. **每个功能必须有"失败的样子"**。没写失败流程的功能视为没设计完。
3. **每个功能必须能被语音触发**（能做的范围内）。开着音箱的时候，人不想掏手机。

## 一、P0 · 没有就不能用

### F1 · 对话（核心）

| 项 | 内容 |
|---|---|
| **触发** | ①网页输入框 ②`POST /api/v1/chat` ③语音（需 L1） |
| **前提** | 配了 LLM Key；没配则走回显模式 |
| **主流程** | 收到文本 → 判断意图 → 调 LLM（≤20s）→ 得到回答 → 播报 → 落历史 |
| **状态** | `思考中…` → `播报中` → `完成` / `失败` |
| **失败** | 网络错：气泡显示 `HTTP 401` 等原始错误 + 「去检查 Key」链接；超时：提示"有点慢，再说一次？" |
| **边界** | 单条输入 ≤ 500 字；历史只留最近 **50 条**；同时只允许 1 个会话在跑 |
| **验收** | 从发起到听到声音 ≤ 3 秒（GLM-4.5-Flash 实测 0.5~1s） |

**意图路由（`IntentRouter`，按优先级匹配，命中即返回，不调大模型）**

```
1. 打断播报   "别说了" / "安静点"                   → SpeechEngine.stop()
2. 闹钟       "明天七点叫我" / "二十分钟后提醒我"     → Config.alarmsJson + AlarmScheduler
3. 音乐       放/暂停/切歌/睡眠定时                    → MusicPlayer
4. 点歌       "放一首七里香"                          → 网易云搜索 → 取地址 → 播放
5. 场景       "晚安" / "早上好"                       → 定时 + 音量 + 天气
6. 查询       几点 / 日期 / 天气 / 系统状态            → 本地或外部 API
7. 运维       重启音箱 / 清理缓存                     → DeviceOps
8. 音量       "调到 40%" / "大声点" / "静音"           → AudioManager
9. 灯环       "开灯" / "关灯" / "呼吸灯"               → 经 L1 调原厂 IPC
10. 智能家居  "打开客厅灯"（配了 HA 地址与令牌才生效）  → Home Assistant REST
11. 其余                                               → LLM
```

> 前三条走本地是为了**快**：设备控制要 200ms 内响应，绕 LLM 就废了。

### F2 · 播报（TTS）

| 项 | 内容 |
|---|---|
| **触发** | F1 拿到回答后自动播；也可单独 `POST /api/v1/tts` |
| **前提** | 配了 TTS 端点（本地服务 / OpenAI 兼容 / 云） |
| **主流程** | 文本 → `POST {ttsUrl}` → 拿到音频字节 → `MediaPlayer` 播 → 播完回调 |
| **状态** | `下载音频` → `播放中` → `完成` |
| **失败** | 端点不通：静默降级（只显示文字，不报错弹窗），但状态栏标记"TTS 不可用" |
| **边界** | 整段 ≤ **2000 字**；按 `。！？；` 切句，单句超 60 字再按逗号切；同时只播一列，新播报打断旧的 |
| **验收** | 首句出声 ≤ 1.5 秒（局域网 TTS）；30 句的长故事能连续播完不断档 |

**⚠️ 必须先验证**：普通 App 的 `MediaPlayer` 在这台机器能不能出声（`archive/open-questions-2026-10-29.md` O-14）。
验证方法：推一个 wav 上去，用我们的 App 播一次，听有没有声音。

### F3 · 状态面板

| 项 | 内容 |
|---|---|
| **触发** | 打开网页（首页顶部常驻） |
| **内容** | 在线状态 / 已运行时长 / `MemFree` / 当前是否在播 / TTS 状态 / L1 是否接入 / 版本 |
| **刷新** | 页面可见时每 **10 秒**拉一次 `GET /api/v1/status` + `/api/v1/config`（播放器每 3 秒）；`visibilitychange` 切到后台即停，回前台立刻补一次 |
| **失败** | 拉不到 → 顶部变红写"连不上"，**不清空上一次的数据**（让人能看到最后状态） |
| **验收** | 拔掉音箱电源，网页 6 秒内变红 |

### F4 · 音量

| 项 | 内容 |
|---|---|
| **触发** | 网页滑杆 / 语音"大声点" |
| **实现** | `AudioManager.setStreamVolume(STREAM_MUSIC, …)` |
| **状态** | 滑杆即时跟手；松手后 300ms 才发请求（防抖），避免刷爆 |
| **边界** | 0~15（这台机器的档位待确认）；0 时图标变静音样式 |
| **失败** | 无（纯本地调用） |
| **验收** | 拖到底，音箱静音 |

---

### F5 · 播放控制

| 项 | 内容 |
|---|---|
| **触发** | 网页按钮 / 语音"下一首" |
| **实现** | 第一期用**我们自己的 `MediaPlayer`**（不碰 player 包），这样不依赖 L1 |
| **状态** | 按钮切换播放/暂停图标；进度条每 1 秒走一次（前端本地插值，不轮询） |
| **边界** | 只支持播放我们发起的音频；原厂/蓝牙播的不受控 |
| **验收** | 点暂停，声音停；再点继续 |

> ⚠️ 局限：控制不了"蓝牙正在放的音乐"和"DLNA 推过来的流"。
> 那是 player 包的领域，要等 L1。

## 二、P1 · 让体验完整

### F6 · 音乐

| 项 | 内容 |
|---|---|
| **触发** | 网页音乐页 / 语音"放一首X" |
| **音源** | ①音箱本地 `/sdcard/Music` ②HTTP 音频流（自己贴直链）③网易云 ④QQ 音乐 |
| **主流程** | 搜索 → 列结果 → 点击 → 取直链 → `MediaPlayer` 播 |
| **语音点歌** | 歌名（放一首稻香）、歌手（播放一首周杰伦的歌，随机挑一首他主唱的歌）、换一首、随便放一首 |
| **登录** | 免版权曲目免登录可播；会员/VIP 曲目要粘 Cookie（网易云需 `MUSIC_U`，QQ 需 `uin` 与 `qm_` + `keyst` 两个键），只存设备本地 |
| **失败** | 搜不到 → "没有搜到 X"；取不到地址 → 分三种情形说清楚（未登录 / 无版权 / 需要会员）；源不通 → 显示原始错误 |
| **边界** | 每次搜索最多 20 条；不缓存音频文件到本地（`/data` 只有 708MB） |

> 实测：**未登录**时网易云的搜索会被翻唱占满（搜「稻香」前 20 条没有一条是周杰伦原唱），
> 周杰伦这类版权曲库基本只能拿到翻唱/合唱；贴上 Cookie 后才是原版。这是数据源的差别，不是代码问题。
>
> QQ 音乐取地址必须带 `zzc` 签名，算法在 `QQMusicProvider.zzcSign` 里自行实现，
> 只用 `MessageDigest` 与 `Base64`，无第三方依赖。

### F7 · 定时任务

| 项 | 内容 |
|---|---|
| **触发** | 网页设置页 / 语音"明天七点叫我"、"二十分钟后提醒我"、"取消闹钟" |
| **实现** | 闹钟存 `Config.alarmsJson`，`AlarmScheduler` 每 15 秒比对北京时间的 `HH:mm` |
| **语音支持** | 中文数字（七点 / 二十三分 / 七点半）、定点（每天）与倒计时（一次性） |
| **一次性** | `once:true` 的闹钟响过自动置为 `enabled:false`，不会第二天同一时刻再响 |
| **边界** | 最多 50 条；分钟级精度；同一分钟多个闹钟合并播一条 |
| **验收** | 设一条 1 分钟后的提醒，准点播报；`GET /api/v1/config` 能看到 `once=true` 的那条 |

### F8 · 灯环

| 项 | 内容 |
|---|---|
| **触发** | 网页首页「灯环」快捷键 / 语音"开灯 / 关灯 / 呼吸灯 / 休眠灯" |
| **实现** | L2 发广播 `com.r1.bridge.cmd{light,mode}` → L1 反射调原厂 `PhicommLightController` |
| **可用效果** | `wakeup`（唤醒色）/ `loading`（呼吸）/ `dormant`（休眠微光）/ `net`（断网）/ `off`（全灭） |
| **失败** | L1 不在线（90 秒无心跳）→ 网页提示"L1 不在线"，语音回答"要我这边在线才能控制" |
| **限制** | 原厂没有任意 RGB 接口，只能选这 5 种预置效果 |

### F9 · 蓝牙

| 项 | 内容 |
|---|---|
| **触发** | 网页首页「蓝牙网关」磁贴（点击开关）/ `POST /api/v1/bluetooth` |
| **实现** | `BluetoothAdapter.enable()/disable()`，设备不支持时返回 409 |
| **边界** | 只控适配器开关；配对与 A2DP 连接由系统蓝牙设置负责 |

### F10 · 投屏接收

| 项 | 内容 |
|---|---|
| **现状** | DLNA/AirPlay 由原厂 `com.phicomm.speaker.player` 提供，**这个包没有动**，仍在系统里 |
| **结论** | 没有开关。DLNA / AirPlay 服务不导出，外部 `am startservice` 会被系统拒绝 |
| **页面能做的** | 点首页徽章会唤醒原厂 `EchoService`，再读 UDP 1900 / TCP 7000 是否在听。端口没开就仍显示未就绪 |
| **为什么不开** | 广播只在原厂自己进入「等待外部连接」时才会起来，这个状态没有对外入口 |

### F11 · 场景

| 项 | 内容 |
|---|---|
| **触发** | 语音"晚安 / 睡觉了"、"早上好 / 起床了" |
| **晚安** | 30 分钟睡眠定时 + 音量降到 20% |
| **早上好** | 报北京时间 + 天气（没配和风 Key 会说明）+ 音量 50% |
| **实现** | `IntentRouter.scene()`，纯本地，不调大模型 |

### F12 · 日志与诊断

| 项 | 内容 |
|---|---|
| **触发** | 网页「系统」页 |
| **实现** | L2 自己维护一个环形缓冲（最近 500 行），`GET /api/v1/logs?tail=100` |
| **不要** | 不要通过 `logcat` 读别人（要权限，且我们只关心自己） |
| **验收** | 出错时能在网页上看到对应那条 |

### F13 · 运维中枢与应用管理（OTA 自升级）

| 项 | 内容 |
|---|---|
| **触发** | ①网页设置页「运维中枢」面板 ②语音"重启音箱"/"清理垃圾" ③`POST /api/v1/apps/*`、`POST /api/v1/system/*` |
| **实现** | 本地回环 ADB (`127.0.0.1:5555`) 穿透特权 (uid=2000) 执行静默操作；纯流式 8KB 循环缓冲直写临时盘避免 OOM |
| **功能** | ①应用管理：列表展示已安装应用、运行状态、占用体积；支持强停与彻底卸载（回收 512MB 内存）<br>②静默安装与空中 OTA：拖拽/选择 APK，流式直写后静默安装；若升级 `com.r1.brain` 自动重启服务生效<br>③一键深度清理：自动清理 `/data/local/tmp` 与音频缓存，触发 JVM GC<br>④特权重启：调用系统 `reboot` 安全重启硬件 |
| **验收** | 拖拽新版 APK，进度条走完后服务自动重启，无需连接电脑 ADB |

### F14 · 开放城市天气（双通道降级）

| 项 | 内容 |
|---|---|
| **触发** | ①语音"今天天气怎么样"/"北京气温多少" ②网页点击「测试天气查询」 ③`GET /api/v1/weather?city=` |
| **实现** | 免 Key 开放源 (wttr.in) 配合 curl User-Agent 返回单行中文天气；和风天气专属 Key 作为备用通道 |
| **降级** | 未配置和风 Key 或官方调用失败时，自动平滑降级至免 Key 开放源 |
| **验收** | 即使零配置 Key，询问任意中国城市天气均可在 1.5 秒内播报实时天气 |

## 三、便捷性设计

### 3.1 语音指令表（当前实装）

| 说什么 | 做什么 | 走本地？ |
|---|---|---|
| 声音大一点 / 小一点 / 音量调到 40 | 音量 ±2 或指定百分比 | ✅ |
| 下一首 / 上一首 / 暂停 / 继续播放 | 播放控制 | ✅ |
| 放一首七里香 | 云音乐搜索并播放 | ✅ |
| 明天七点叫我 / 二十分钟后提醒我 | 加闹钟（一次性/每天） | ✅ |
| 取消闹钟 | 关闭全部闹钟 | ✅ |
| 现在几点 / 今天几号 | 本地时间 | ✅ |
| 今天天气 / 杭州天气 | 和风天气或免 Key 开放源 | ✅ |
| 晚安 / 早上好 | 睡眠定时 + 音量 + 天气 | ✅ |
| 开灯 / 关灯 / 呼吸灯 / 休眠灯 | 灯环（经 L1） | ✅ |
| 打开客厅灯 / 关闭客厅灯 | Home Assistant（需配置） | ✅ |
| 别说了 / 安静点 | 打断当前播报 | ✅ |
| 清理垃圾 / 系统体检 / 重启音箱 | 运维 | ✅ |
| （其它） | LLM | ❌ |

### 3.2 手机上怎么最快打开

| 方式 | 落地 |
|---|---|
| **PWA**（推荐） | 加 `manifest.json`，安卓 Chrome "添加到主屏幕"，之后一点就开，像 App |
| 二维码 | 打一张贴音箱底下 |
| 书签 | 零成本 |

### 3.3 减少点击次数

- 首页 = 正在播放 + 4 个快捷 + 输入框，**常用动作 0~1 次点击**
- 开关类控件**即时生效**，不等"保存"按钮（现役页面要保存才生效）
- 表单类（Key、地址）才需要保存

## 五、明确不做的

| 不做 | 原因 |
|---|---|
| 多房间 / 多设备 | 只有一台 |
| 手机原生 App | 网页 + PWA 够了 |
| 扫码登录音乐源 | 要客户端渲染二维码 + 中转轮询，收益不抵成本；粘 Cookie 已经够用 |
| 语音唤醒自己实现 | 麦克风被原厂独占（D-04） |
| 在设备上存音乐 | `/data` 只剩 708MB，且没必要 |
| 复杂动画 | 渲染能力有限 |
| 灯环任意 RGB | 原厂只暴露 5 种预置效果，没有颜色参数接口 |
| 接管 DLNA / AirPlay | 原厂 player 包仍在，接管风险大于收益 |
