# 8080 的性质（实测结论）

> 这个问题被反复问过，这里一次性钉死。

## 一句话

> **8080 是「我们刚刷进去的这个 MOD 安装包」自己带的，不是原厂固件自带的。**
> 而且它是**第三方作者后加的**——原厂那个同名 App 里压根没有网页服务。

## 证据：原厂 vs 现役，逐项比对

我把设备上两个包都拉下来拆了：

| 对象 | 路径 | 大小 | 文件头 |
|---|---|---|---|
| 原厂 | `/system/app/Unisound/Unisound.apk` | 24,936,387 | `PK\x03\x04`（标准 ZIP） |
| 现役 | `/data/app/com.phicomm.speaker.device-1/base.apk` | 33,064,967 | `dex\n035\0`（Janus） |

**现役包拆开**：

```
[ 0 .. 8,128,579 ]        前置 DEX      ← MOD 作者加的代码
[ 8,128,580 .. 33,064,967 ]  zip 部分   24,936,387 字节 ← 跟原厂一样大
```

**这个 zip 部分和原厂 Unisound.apk 做了逐字节比对：**

```
总字节数 24,936,387，不同的只有 405 字节
差异全部位于 offset 24,925,337 之后（即 ZIP 中央目录区）
```

那 405 个差异是**中央目录里的本地头偏移字段**（每条约 3 字节 × 134 条 + EOCD），
也就是 Janus 构造时「把所有偏移 +8,128,580」必然产生的改动。
**条目内容、资源、签名，一个字节都没变。**

> 换句话说：**MOD = 原厂 APK（原封不动）+ 前面贴了一段自己的 DEX。**

## 网页到底在哪一份里

对两个 DEX 分别搜索关键词：

| 关键词 | 原厂 dex (6,067,068 B) | 前置 DEX (8,128,580 B) |
|---|---|---|
| `8080` | 7（全是内网旧地址，见下） | **10** |
| `<!DOCTYPE` | **0** | **1** |
| `Server started on port 8080` | 0 | **1** |
| `toggle_ambient_light` | **0** | **2** |
| `save_config` | **0** | **5** |
| `alarm_add` | **0** | **3** |
| `qw_pubkey` | **0** | **3** |
| `set_wakeup` | 1 | **4** |

原厂 dex 里那 7 个 `8080` 是什么：
```
http://10.30.4.12:8080/data-cloud-service/rest/v1/music/get_song_by_id
http://10.200.19.108:8080/app_wx_adapt_service/m/uploadAppLogFile
http://10.30.2.231:8080/app_wx_adapt_service/m/getCustomerConfig
http://106.14.226.237:8080/service/iss-test?platform=&screen=&text=
```
**全是斐讯内网的接口地址，没有一个是本地监听。**

原厂 dex 里 `<title>`/`<!DOCTYPE`/`斐讯R1配置` 全部为 **0**，assets 里也没有任何 .html。

## 还有两条旁证

**1. 运行期归属**：`/proc/net/tcp6` 里 8080 那行的 uid = `10008`，
而 `com.phicomm.speaker.device` 实测 uid 就是 10008。

**2. 文件里根本没有网页资源**：现役包里 134 个条目，`res/` 下全是 png，
`assets/` 下全是语音模型和配置，**没有一个 HTML 文件**。
所以那个 29,341 字节的页面是**硬编码在 DEX 里的字符串**。

## 时间线

| 时间 | 事件 |
|---|---|
| 2023-06-22 | 设备上原来的 `com.phicomm.speaker.device`（出厂/早期更新） |
| 2026-10-28 20:23 | **我们装了这个 MOD**（`pm install -r`） |
| 现在 | 打开 8080 看到的「斐讯R1配置 1.0.4」页面 |

页面本身是**在我们装之前就存在的吗**？——**不是**。
装之前那台机器上的 `com.phicomm.speaker.device` 是哪一版我们没留证据，
但 8080 这套接口（22 个）和页面，**全部来自我们装的这个 DEX**。

## 结论

- ❌ 原厂固件不带 8080。
- ❌ `com.phicomm.speaker.player`（原厂 EchoService，1.1MB）不带 8080。
- ✅ **我们装进去的这个 MOD 带的**，作者在 DEX 里硬编码了一份网页 + 一个小 HTTP 服务器。
- 这也解释了为什么它没有鉴权、为什么接口是裸 GET——那是作者自己写的玩具级服务器。

## 对设计的影响

**如果我们要自己设计，8080 完全不需要兼容。**
它没有任何历史包袱（原厂从来没有过），接口也是作者随手定的。
我们想怎么开端口、怎么鉴权、用什么协议，全部自由。
