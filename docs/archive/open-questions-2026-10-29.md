## A. 需要你拍板

### A1 · ✅ 已定：OpenAI 兼容，Key 后配

不做厂商绑定。请求体走标准 `/chat/completions`，`base_url` / `model` / `key` 都可配。
**你现在不用给 Key**，没配时返回"回显模式"，所有链路照样能跑。

> 唯一提醒：如果之后选智谱，**别用 GLM-4.7** —— P1 项目实测同一条问题要 27~68 秒（4.5-Flash 只要 0.5~1 秒）。

### A2 · 音乐源 → 放到阶段二，多源支持

你的意见：**支持多家（网易云 / QQ 等），但不阻塞，后面做。**
补充一个候选：**Songloft**（原 MiMusic，Docker 镜像 `songloft/songloft`，
默认端口 **58091**，有 REST API `/api/v1/*` 和 Swagger，JS 插件扩展音源）。

阶段一不做音乐源，只用本地文件验证播放通路。
| 本地文件 | 最简单，但要往设备存歌（只剩 708MB） |

> 现状：MOD 的网页里留的是 `http://ip:4533`（Navidrome 默认端口），说明原作者也走这条。
> **但我不知道你是否有这台服务在跑**，需要你确认地址。

### A3 · ✅ 已定：暂时不接 Home Assistant（不做）

- 接：一句话能控全屋设备（"把客厅灯关了"）
- 不接：只能控音箱自己

> 你确认暂时没有 HA，**一阶段不做**。接口留好，以后要接只加一个适配器。

### A4 · 音色与语速的默认值

| 项 | 可选 | 建议 |
|---|---|---|
| 音色 | alloy / echo / fable / onyx / nova / shimmer | `nova`（女声，偏自然） |
| 语速 | 0.7 ~ 1.5 | `1.0` |
| 默认音量 | 0~15 | `8` |

### A5 · M2 持续对话，"听"由谁触发 ⛔ 阻塞 L1 接口

| 选项 | 体验 | 代价 |
|---|---|---|
| 每轮都要说"小讯小讯" | 安全、省电 | 不像打电话 |
| 播完自动续听 5 秒 | 像打电话 | 会误识别环境音；需要 VAD |
| 播完提示一声再续听 | 折中 | 提示音有点吵 |

> 建议**自动续听 5 秒**（豆包打电话模式就是这么做的）。

### A6 · 接不接受"先播缓存短语掩盖延迟"

现象：LLM 回完到开口要 2.4 秒。如果先播一句预设的"嗯，我想想"，能立刻有反应。

- 接受：体感快很多
- 不接受：安静 2.4 秒再开口

> 建议**接受**，但要做得自然（随机几句，别每次都说同一句）。

### A7 · 句间空隙能不能忍

分句播放时，`MediaPlayer` 每换一个文件会有 100~200ms 断点。

- 能忍 → 用 mp3 + MediaPlayer（简单）
- 不能忍 → 合成后解码成 PCM 拼成一条流喂 `AudioTrack`（多一层代码）

> 建议**先按 mp3 做，实测听感再决定**。这条不阻塞。

### A8 · 定时任务要不要"法定节假日"

工作日闹钟要不要跳过法定节假日（比如国庆调休）。

- 要：得维护一张节假日表（MOD 用的是 jieri8.com）
- 不要：只按周一到周五

> 建议**先不要**，第二期再说。

### A9 · 多条任务同时到点

- 排队播（一个接一个）
- 后到的打断先到的
- 合并成一句

> 建议**排队播**，简单且不会漏。

### A10 · L1 什么时候做 ⛔ 影响整个后半程

| 选项 | 好处 | 坏处 |
|---|---|---|
| 现在做 | 灯环/唤醒/投屏能早点有 | 风险高，且业务层还没验证 |
| **L2 全部做完再做**（建议） | 风险后置，L2 能独立交付 | 灯环要等 |
| 不做 | 最省事 | 永远只能当"外挂"，拿不到灯环和语音唤醒 |

### A11 · L3 第一期起不起

> 建议**不起**。L2 自己供静态页就够，少一台机器的依赖。

### A12 · 远程访问什么时候做

> 建议 **M1 完成之后**。跳板方案已写好（`08-http-api.md` §3.2），不费事但要额外一台常开的机器。
