## A. 主界面（最明显的问题）

设备屏幕上只有 `Pandora` 青底测试页：测试用例界面 / 禁用MIC / 上一首·播放·下一首 / 联网。

| 可选做法 | 代价 | 可行性 |
|---|---|---|
| 只换 `launcher` 的桌面，MOD 的 Activity 不动 | 低 | 高，`com.phicomm.speaker.launcher` 是独立包 |
| 直接替换 MOD 的 `MainActivity` | 需要反编译 + 重签 | 中，能装但会丢签名一致性（本来就是自签，无所谓） |
| 做一个本地网页当控制台，屏幕继续放着 | 最低 | 高，8080 已经在做一半 |

## B. 配置网页（8080）

现状：六个标签页，功能齐但很难看、没有状态显示、没有实时反馈。

- 能不能直接改它的前端？→ **要先确认前端资源在 APK 里还是内置在 dex 里**
- 有没有 JSON API 可以调？→ 抓包或反编译找路由
- 如果 API 是干净的，可以自己写前端，保留后端

## C. 语音链路

| 现状 | 想做的 |
|---|---|
| 唤醒词「小讯小讯」，5 种音色可换 | 支持更多唤醒词 / 昵称 |
| 大模型默认智谱 GLM-4.5-Flash，需填 Key | 换成本地 Ollama？低延迟、不出网 |
| 无 Key 时走 HA / 本地路由 | 本地路由能干什么？需要摸清 |

## D. 音乐源

- 网易云 `:3000`（NeteaseCloudMusicApi 那套？）
- QQ 音乐 `:3300`（QQMusicApi）
- Navidrome `:4533`
- **都在局域网其他机器上跑，R1 只当客户端** —— 那台机器是谁？要不要在本机 docker 起来？

## E. 硬件能力是否被浪费

- 有氛围灯（`#btn-light`），实际效果如何？有没有动画？
- 低音增强（`#btn-bass`），是软件 EQ 还是驱动层？
- 麦克风阵列：能不能做「声源定位 / 唤醒方向」
- 屏幕（如果这块屏是可显示的）—— 目前只用来放测试页，浪费

> **实测硬件上限**（2026-10-28 `r1-doctor` 结果）：
> 内存总共 501,444 kB（≈490MB），空闲仅 5,796 kB —— **内存非常紧**，
> 任何「多装一个常驻服务」的方案都要先算这笔账。`/data` 988MB，已用 279.9MB，剩 708MB。

## F. 系统层面

- `SysPrivateService.get BootProp` 失败 —— 非系统签名拿不到 boot prop，可能挡住某些系统能力
- `otaservice` 还在跑，**可能会把 MOD 覆盖回出厂版**？要不要禁掉
- 5555 敞开，是否要关（`setprop service.adb.tcp.port -1`）

## 下一步建议顺序

1. 先搞清楚 8080 的 API（决定能不能做自建前端，牵涉面最大）
2. 摸清主界面能不能换（体验层面最直接）
3. 再谈 AI / 音乐源（这些是配置层的事，随时能改）
