# 16 · 控制台 UI 设计提示词（投喂设计工具用）

> 用途：把下面【提示词正文】整段复制给 UI 生成工具（Figma Make / v0 / Lovable / Stitch / Claude 等），
> 让它出几套首页与整体排版方向给我们挑。
> 说明：只锁**产品语境、内容清单、气质方向和落地约束**；色值、字号、间距、圆角这些
> 一律不预设，交给设计工具自己定并出标注。
> 现有对比基线：`web/desktop` 与 `web/mobile` 的 8 个已实现页面（黑金版）。
> 历史原型已删除，设计语言以当前实现为准。

---

## 提示词正文

```
你是一位资深产品设计师，为一个「智能音箱控制台 Web UI」做界面设计。请先给出 3~4 个
不同的首页布局方向（各自的取舍说明），再给出配套的其余页面排布。如果你能生成代码，
请按最后的「落地约束」输出单个 HTML 文件；如果只能出图，请出高保真视觉稿 + 标注。

────────────────────────────────────────
一、这是什么产品
────────────────────────
一台被改造的斐讯 R1 音箱（旧安卓硬件）。设备里跑一个轻量 HTTP 服务，这个 Web 页面是
它唯一的控制台：看设备状态、跟它说话、听它回答、调语音和音乐、改配置。

用户是同一个人（设备主人），使用场景按频率排序：
1. 手机上、客厅、单手、站着、光线偏暗，瞄一眼状态或发一句话 —— 每天十次以上
2. 手机浏览器 / 微信小程序内嵌 web-view / ZeroTier 远程 / 公网反向代理
3. 桌面浏览器（电脑在同一局域网）调试与配置 —— 一周几次
所以：移动优先，桌面是「同一套内容换个排布」，不是另做一个后台系统。

它是一台音响的控制面板，不是后台管理系统。气质参考 B&O / Naim 这类音响的质感：
克制、安静、贵一点，不要 admin dashboard 的样子。

────────────────────────────────────────
二、气质方向（只锁方向，数值你来定）
────────────────────────
· 深色底、低饱和、单一暖色做强调；不要蓝紫科技色，不要多彩语义色堆叠
· 主次靠亮度层级和细描边拉开，不靠重阴影、玻璃拟态、彩色投影
· 金色/强调色只给「活着的东西」：当前标签、正在播放、主操作、当前状态；其余一律灰
· 界面里数字（时间、内存、进度）要在跳动时不位移
· 只有两种动效：正在播放的音柱、切页时的轻微淡入；不要转场、骨架屏、粒子、视差
· 不要：亮色/双主题、照片插画或 emoji 当图标、卡片套卡片、大面积渐变、
  外部字体和图标库（图标只能是内联线性 SVG）

色板、字号阶梯、间距尺度、圆角、栅格由你决定，并在最后给出你自己的设计标注。
不要沿用常见后台模板的那套数值，我们要它看起来像音响，不像管理系统。

────────────────────────────────────────
三、必须容纳的内容（信息架构）
────────────────────────
5 个一级标签，手机在底部标签栏、桌面在侧边导航：
首页 · 对话 · 语音 · 音乐 · 设置

全局常驻状态栏，必须一眼看到，三态：
  在线 / 演示模式（静态预览，没连上设备）/ 连不上（有令牌但请求失败）
状态栏内容：设备名「R1 · 控制台」+ 状态 +「已运行 2 小时 · 内存 16.2M · L1 未接入」
（L1 = 设备原厂唤醒/语音桥，还没接上，所有依赖它的控件必须显示为只读并标「需 L1」）

【首页】需要这些模块，但它们的大小、位置、分组、是否折叠，全部由你决定：
  · 正在播放：曲目「七里香」/「周杰伦 · Navidrome」/ 进度 1:42–4:59 / 上一首·暂停·下一首
  · 输入框：占位「说点什么…」+「发送」（回答会从音箱播出来）
  · 最近一轮对话：我问「帮我讲个笑话」，答「有一只鸭子走进酒吧，问老板：有葡萄吗？
    老板说没有。第二天鸭子又来，还是问：有葡萄吗？老板有点烦……」+「重播 · 1.2s」
  · 快捷操作（4 个）：氛围灯（开）· 音量 40 · 蓝牙 · 休眠
  · 设备信息（可选，也能收进二级）：状态 / 已运行 / 可用内存 / L1 桥接 / 服务端口 8686
  · 版本 v0.1.0

【对话】页面标题 +「今天 6 条」+「清空」；一排快捷指令（现在几点 / 杭州天气 /
播放七里香 / 关客厅灯 / 讲个笑话）；问答气泡列表（我=一侧暖色底，助手=另一侧卡片底），
每条助手回答下有「重播 · 复制 · 耗时」；输入框固定在底部标签栏之上。

【语音】三组：语音输出（局域网服务 / OpenAI 兼容 / 云厂商 三选一 + 服务地址 + 音色 +
语速 +「试听一句」+ 上次试听结果）；唤醒（唤醒词、灵敏度，均只读、标「需 L1」）；
播报行为（自动播报回答、播报时压低音乐、播报音量）。

【音乐】当前播放迷你条；搜索（歌曲/歌手，结果显示歌名·歌手·时长·播放）；
音乐源（Navidrome 已连接 / 网易云 未配置 / QQ 音乐 未配置）；投屏接收（DLNA、AirPlay
未启用，蓝牙可用）。

【设置】大模型（接口地址 / API Key 默认打码带「显示」眼睛 / 模型 GLM-4.5-Flash /
温度 /「测试连通」+「保存」/ 上次保存时间）；集成（Home Assistant、天气，均未配置）；
系统（运行日志、固件升级、重启服务）；高级操作（清空配置、重启设备）必须默认折叠，
展开后是危险语义，且执行前二次确认。

内容/交互规则：
· 每个动作要有回执：内联状态行或轻提示（toast），不要用 alert 弹窗
· 失败要显示原始错误（如 HTTP 401），并给一条「去设置检查 Key」的跳转
· 危险操作一律折叠 + 二次确认
· 常用在第一屏，配置收进二级

────────────────────────────────────────
四、两套尺寸
────────────────────────
同一套内容，两种排布，都要出：
· 窄屏：手机竖屏（含最窄的常见机型，不横向溢出；微信 web-view 同样成立）
  底部标签栏常驻，输入框落在标签栏正上方，注意刘海与底部安全区
· 宽屏：桌面浏览器，侧边导航 + 主内容区
宽屏不许「空洞」：要么加信息密度，要么把二级收进来，不要两个大卡片中间一片黑，
也不要靠把卡片拉宽来填空。窄屏不许拥挤：首屏要有一个明确的第一视觉落点。

────────────────────────────────────────
五、落地约束（如果要代码）
────────────────────────
· 单个 HTML 文件，内联 CSS/JS/SVG，零外部资源、零框架、零构建
· 原生 JS（ES5 兼容写法优先，需在微信内置浏览器、旧版 Android WebView 上能跑）
· 未压缩体积目标 < 60 KB
· 页面由访问端浏览器渲染（手机/电脑），设备只负责提供 API
· 数据来自这些接口（相对路径，鉴权用 X-Token 请求头）：
  GET  /api/v1/status  → { ok, uptimeMs, memFreeKb, l1 }
  POST /api/v1/chat    → { ok, reply, costMs } 或 { ok:false, error }
  GET/POST /api/v1/config
· 拿不到接口时（比如静态预览）自动进入「演示模式」，用本地假数据回复，不能白屏或报错刷屏

────────────────────────────────────────
六、上一版的毛病，请务必避开
────────────────────────
现有一版被判定「首页布局很奇怪」，问题都是排版层面的：
1. 首屏被固定输入条压掉一大块，内容在它上方被切成半截（「设备」标题露出来但卡片整块
   看不见），像加载中而不是设计
2. 播放器卡片在手机上过高过突出，但首页第一目的其实是「说一句话」
3. 快捷操作、最近对话、设备三组内容平铺在同一层级，没有主次，扫一眼抓不到重点
4. 桌面端劈成两列后右列很短、下方一大片黑，两列高度不对齐，显得空洞
5. 顶部已有「R1 · 控制台」，下面又跟一个页面大标题，两层标题重复占高
6. 输入条和底部标签栏叠成一条深色带，看起来像两个栏叠在一起，边界不清

请重新决定：首页第一眼应该是什么（是「说一句话」这件事，还是播放状态？）、
快捷操作要不要和状态合并、播放器应该在哪、设备信息是否值得占据首屏、
宽屏怎么用三层而不是两列把宽度用起来。可以给 3~4 个方向并各写一句取舍理由，
例如「输入优先」「播放优先」「状态优先」「极简首屏 + 二级展开」。

输出顺序：① 首页 3~4 个布局方向（含取舍）→ ② 选定方向下的其余 4 页 → ③ 设计标注
（色板、字号阶梯、间距尺度、圆角、栅格、组件清单——这些由你定）。
```
