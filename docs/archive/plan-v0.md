# 总计划 · 两个阶段

> 这是整个项目的入口文档。看完这篇就知道：做什么、分几步、每步怎么算完成。
> 最后更新：2026-10-29

---

## 一句话

给斐讯 R1 重做一个能对话、能播报、能定时、能放歌的助手，并且**能自己更新、能退回原厂**。

---

## 为什么只分两个阶段

| 阶段 | 边界 | 为什么这样切 |
|---|---|---|
| **阶段一** | **只做 L2** —— 不碰设备身份，不装 L1 | 90% 的工作量在这里，而且**零风险**：装坏了 `pm uninstall` 就没了 |
| **阶段二** | **L1 + 收尾** —— 顶替原厂包，拿唤醒/灯环/投屏 | 高风险的一次性投入，必须等业务层验证过才值得动 |

> 中间不再插阶段。阶段一没做完不进阶段二。

---

## 阶段一 · L2（能用）

### 目标

**手机打开网页，就能对话、能让音箱说话、能设闹钟、能放歌。**
不需要唤醒词，不需要灯，不需要动原厂任何东西。

### 功能清单（8 项）

| # | 功能 | 依赖 | 验收 |
|---|---|---|---|
| **F1** | 对话（网页/HTTP/广播） | LLM（OpenAI 兼容，Key 后配） | 发一句，返回合理回答，记下耗时 |
| **F2** | 播报（TTS） | TTS 服务 + `MediaPlayer` | 音箱出声，`card2` 播放节点变 RUNNING |
| **F3** | 状态面板 | `/proc` | 内存/运行时长/L1 状态实时刷新 |
| **F4** | 音量 | `AudioManager` | 拖滑杆，音量真的变 |
| **F5** | 播放控制 | 自己的播放器 | 播放/暂停/继续，本地文件能放 |
| **F6** | 定时任务 | `AlarmManager` | 1 分钟后的闹钟准点响，重启后还在 |
| **F7** | 配置界面 | 8686 + 鉴权 | 五个页面都能用，改完立即生效 |
| **F8** | 日志 | 环形缓冲 | 网页能看到最近 100 行 |
| **F13** | 运维中枢与OTA自升级 | 本地回环 ADB (`127.0.0.1:5555`) | 网页直接上传 APK 空中自升级，卸载应用回收内存，特权重启与清理 |
| **F14** | 开放城市天气 | wttr.in 开放源 + 和风天气 | 默认免 Key 即可查询全国城市天气，支持和风天气双通道自动降级 |

### 界面（5 个标签 + 1 个二级页）

| 页面 | 内容 |
|---|---|
| **首页** | 状态条 · 正在播放 · 4 个快捷（灯/音量/蓝牙/休眠，前三个在阶段一置灰标"需 L1"）· 下一个定时任务 · 对话输入 |
| **对话** | 完整历史（上限 50 条），可重播 |
| **语音** | TTS 地址/音色/语速/试听；唤醒词（灰） |
| **音乐** | 源配置（阶段一只做本地文件）；当前播放 |
| **设置** | 大模型 · 系统（日志/升级/危险区） |
| **任务（二级页）** | 从首页卡片进入，增删改 |

### 拆解（每步都能独立验收）

| 步 | 内容 | 验收 | 预计 |
|---|---|---|---|
| **S1** | 验证 V1（能否出声）、V2（定时准不准） | 两条客观证据齐全 | 0.5 天 |
| **S2** | F4 音量 + F8 日志 | 网页能调音量、能看日志 | 0.5 天 |
| **S3** | F2 播报（单句） | 音箱真的说话 | 1 天 |
| **S4** | F2 播报（分句 + 并发 + 缓存） | 长回答不卡，首音 ≤2.5s | 1 天 |
| **S5** | F5 播放控制 + 本地文件 | 能放一个 wav/mp3 | 0.5 天 |
| **S6** | F6 定时任务（含 chime 兜底） | 闹钟准点响 + 重启不丢 | 1 天 |
| **S7** | F7 界面补全（语音页/音乐页/设置页/任务页） | 五页都能操作 | 1.5 天 |
| **S8** | F3 状态面板接活 + F1 接 LLM | 配 Key 后能真对话 | 0.5 天 |

**合计约 6.5 个工作日**（不含你确认的时间）。

### 阶段一验收（三个场景）

1. **对话**：手机打开网页 → 输入"今天天气怎么样" → 2 秒内音箱开口回答
2. **闹钟**：设一条 2 分钟后的任务 → 到点响（先 chime 再播报）
3. **断电**：拔电源再插上 → 服务自动起来，闹钟还在，网页能打开

### 阶段一交付物

- `l2-app/` 可编译可安装的完整工程
- 网页（内嵌在 apk 里）
- `docs/` 里对应的验收记录
- 一个能用的音箱（虽然还得掏手机）

## 阶段二 · L1 + 收尾（好用）

### 目标

**叫得醒、灯会亮、手机能投屏、能自己升级。**

### 内容

| # | 内容 | 说明 |
|---|---|---|
| **F9** | 多音乐源 | Songloft / Subsonic 兼容库 / 网易云 / QQ（按你能提供的来） |
| **F10** | 意图路由 | 语音/文本 → 本地动作优先（关灯、定时、播放），其余走 LLM |
| **F11** | 场景 | 一句话执行一串动作 |
| **F12** | 灯环 | 需 L1：`ISysPrivate` + `MessageDispatchManager` |
| **F13** | 蓝牙模式开关 | 在 player 包里，需摸 |
| **F14** | 投屏接收 | DLNA / AirPlay，当前未广播，需激活 |
| **—** | 自升级 | 网页上传 apk → 设备自安装（摆脱 adb） |
| **—** | 稳定性 | 长跑一周不崩、内存不涨 |
| **—** | 文档定稿 | 把两阶段的实际结果写回去 |

### 阶段二的风险

| 风险 | 应对 |
|---|---|
| L1 顶替把语音助手弄坏 | 先备份现役 apk；`pm uninstall` 可回原厂 |
| 灯环调不通 | 直接删掉 F12，不影响其它功能 |
| DLNA 激活不了 | 用蓝牙替代 |
| 每次改 L1 都要重打包 | L1 只做转发，业务逻辑不放进去 |

### 阶段二验收

1. 说"小讯小讯，今天天气" → 音箱回答（不需要掏手机）
2. 说"开个氛围灯" → 灯亮
3. 手机投屏到音箱 → 能放
4. 网页点升级 → 装上新的 L2，不用 adb

## 明确不做

| 不做 | 原因 |
|---|---|
| 自己实现唤醒词 | 麦克风被原厂独占（`09-decisions.md` D-04） |
| 手机原生 App | 网页 + 加到主屏就够 |
| 多房间 / 多设备 | 只有一台 |
| 在设备上存音乐 | `/data` 只剩 708MB |
| 自建 DLNA 渲染器 | 内存不够，且 player 包已有 |

## 现在从哪开始

**S1：验证 V1 和 V2**

- ✅ **V1：`MediaPlayer` 能出声** —— 2026-10-29 实测（`tools/play-probe`），普通 App 用
  `MediaPlayer` 播 wav，`duration=4148ms` / `START→COMPLETED=4168ms` 吻合，人耳确认听到。
  注意：`card2/pcm0p` 的 RUNNING **不能**当判据（AudioFlinger 常驻，见 `05-voice.md` §九）。
- ✅ **V2：`setExact` 准** —— 2026-10-29 实测：120 秒间隔 `drift=5ms`，到点响了（人耳确认）。
  1 小时长间隔另排了一条观察（验证进程被回收后 alarm 仍能拉起接收者）。

**S1 已完成，进 S2。**

两条都过 → 直接进 S2。
哪条不过 → 对应功能换实现（`05-voice.md` / `06-scheduler.md` 里都写了备选）。
