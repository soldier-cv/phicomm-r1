# 斐讯 R1 音箱 —— 重做语音助手

> **新人从 `START-HERE.md` 开始读。** 本文只是仓库说明。

给一台原厂云服务已死的斐讯 R1 重做一个能用的语音助手：
保留原厂的唤醒与收音，换掉已经死掉的「大脑」。

## 一眼看懂的三层架构

```
L3  控制面（电脑/NAS）—— 配置、日志、部署        【已落地：8 个静态页面】
L2  业务 App（com.r1.brain）—— 全部业务逻辑      【日常迭代都在这里】
L1  桥（Janus 顶替 device 包）—— 唤醒/ASR/灯环  【已落地：很少改，改一次要重打包】
```

核心思想：**把「能力」和「迭代」拆开** —— 能力留在 L1（不常变），业务放 L2（天天变）。

## 快速开始（一键安装）

仓库已内置开箱即用的交付工具包：

1. 确保斐讯 R1 音箱已开机并与电脑处于同一局域网 Wi-Fi。
2. 双击运行 **`一键安装包/一键安装.bat`**。
3. 按照提示输入音箱的局域网 IP 地址，脚本将自动完成连接、上传、静默后台安装并启动后台服务。
4. 安装完成后，在浏览器访问控制台：
   - 电脑端：`http://<音箱IP>:8686/desktop/home.html`（黑金机架式左侧导航栏布局）
   - 手机端：`http://<音箱IP>:8686/mobile/home.html`（黑金紧凑式底部导航栏布局）
   - 访问根路径 `http://<音箱IP>:8686/` 时会自动根据设备类型智能分流重定向。

## 配置

本项目所有配置均为**热加载配置**，直接在 Web 控制台（`http://<音箱IP>:8686/desktop/settings.html`）或通过 REST API (`/api/v1/config`) 修改即可即时生效，**不依赖且不需要任何本地 `.env` 环境变量文件**。

核心配置项说明：

| 配置项 | 控制台入口 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| 大模型 Key / 端点 | 设置页 → 大模型 | 是 | 空 | OpenAI 兼容接口（Base URL / API Key / 模型名称） |
| ASR 语音识别地址 | 设置页 → 语音识别 | 是 | 自建网关 | 自建 ASR 语音服务网关（如 `http://<网关IP>:8710`） |
| TTS 语音合成 | 设置页 → 语音播报 | 否 | 原厂 TTS | 优先级：HTTP TTS → 原厂 TTS（经 L1 桥接）→ 系统 TTS |
| 城市天气 Key | 设置页 → 基础功能 | 否 | 空 | 和风天气专属 Key（留空自动降级走 wttr.in HTTP 免 Key 查询） |
| 控制台访问令牌 | 设置页 → 安全设置 | 否 | 空（首次开放） | 需自行设置才生效；设置后 `/api/**` 强制校验，可用 `?token=` 传入。暴露到网络前建议设置 |
| 音乐平台凭据 | 音乐页 → 曲库配置 | 否 | 匿名模式 | 网易云 MUSIC_U Cookie / QQ 音乐登录凭据，用于获取无损音质 |

ASR 网关接入步骤（语音识别唯一通道）：

1. 在 asr-gateway 控制台「调用令牌」页发放一枚带 `short` scope 的令牌，复制明文。
2. 在本项目设置页 → 语音识别，引擎选「自建 ASR 网关」，地址填 `http://<网关IP>:8720`，令牌填上一步的明文。
3. 点「查看网关用量」验证连通（不计次数），再点「上传 WAV 识别测试」验证真实转写。
4. 令牌与额度由网关侧管理；网关返回 `QUOTA_EXCEEDED`（429）时本项目停止调用并播报额度提示。

完整契约与历史证据见 `docs/24-self-hosted-asr.md`；网关侧接口见 `docs/INTEGRATION.md`。

## 设备

| 项 | 值 |
|---|---|
| IP | DHCP 分配（建议在路由器绑定 MAC 固定） |
| MAC | 以你自己设备上的为准（路由器客户端列表可查） |
| 型号 / 安卓 | `rk322x-box` / 5.1.1 (API 22) |
| 内存 | 490 MB 总，清理后可用约 25 MB（仍不建议在设备上跑重服务） |
| 我们的 L1 | Janus 顶替 `com.phicomm.speaker.device`，底包是原厂 `Unisound_original.apk` |
| 回退目标 | `/system/app/Unisound`（原厂，未动） |

## 当前设计前提

1. **麦克风只有一个，被原厂链独占** → 我们不能自己采，由 L1 转发 ASR 结果
2. **Janus 可以顶替原厂包** → L1 就是这么做的
3. **控制面是我们自己写的 8686** → 原厂固件没有 HTTP 控制服务；第三方 MOD 曾在 8080 提供配置页，顶替 MOD 包后已不存在
4. **灯环要通过原厂 `PhicommLightController`**，需要进程身份 → 灯控留在 L1
5. **清理后可用内存约 25MB** → 设备上不适合跑重服务，L2 的轻量 HTTP 服务可以
6. **adbd 不稳定** → 部署不依赖 adb，优先网页 OTA

> 历史形态（第三方包里的 8080 配置页等）已归档到 `docs/archive/`，与当前系统无关。
